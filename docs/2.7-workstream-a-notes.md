# AnchorDesk 2.7 — Workstream A notes

## Design calls

- `TicketEvent` remains downstream of the existing in-process event bus. Audit
  rows are written transactionally first; the second subscriber writes metric
  facts afterward. `(sourceAuditId, kind)` is the durable idempotency identity,
  so a live delivery and the next boot's audit reconstruction converge on one
  row. Scheduler facts use a deterministic `sourceKey` containing the frozen
  SLA snapshot identity.
- A status transition produces exactly one status fact: `resolved`, `reopened`,
  or `status_changed`. Merge stays distinct. Assignment and context facts may
  coexist with that status fact when one audited mutation changes several
  dimensions.
- I added `context_changed` beyond the starting event vocabulary. Without it,
  later time/SLA queries could not recover company or priority at an arbitrary
  point without consulting the mutable ticket row. Company/team foreign keys
  now restrict deletion until their tickets have gone through the normal
  audited update path; legacy company linking uses that path too.
- SLA snapshots deliberately have no relation or foreign key to `SlaPolicy`.
  Policy deletion cannot erase provenance. Database triggers reject update and
  delete on both reporting tables; a legitimate open-ticket re-target appends a
  new snapshot. A nullable snapshot is an append-only “no SLA” marker when a
  real target is removed. Reprioritizing an already-terminal ticket does not
  manufacture a new promise.
- SLA compliance treats each snapshot as an active interval, ordered by
  `(establishedAt, id)`. A completed promise remains countable after a later
  re-target; an uncompleted promise replaced before its deadline is not judged.
  In addition to the requested `met`, `breached`, and `atRisk` counts, the query
  returns `onTrack` because those three categories are not exhaustive.
- Audited facts use `sourceAuditId` as the causal tie-breaker; subscriber insert
  order is not treated as event order. Raw report/backfill timestamps are
  normalized to Prisma's UTC-naive PostgreSQL `TIMESTAMP(3)` representation, so
  day buckets do not depend on the database session timezone. An SLA breach is
  recorded at the due instant (or when an already-overdue re-target is
  established), with dimensions recovered from the event spine at that instant.
- `workedAt` is recorded once. A windowed entry always uses `timeStart`; an
  explicit `workedAt` is accepted for duration-only work; otherwise the exact
  note `createdAt` is stored. REST and MCP reject a conflicting window plus
  `workedAt` instead of silently choosing one. Historical time attribution uses
  `originTicketId` after a merge.
- Report ranges are `[from, to)` UTC instants. Day volume uses UTC calendar
  buckets. The assignee filter on time means the technician (`Note.authorId`);
  event reports use the denormalized ticket assignee.

## Backfill and indexes

The boot migration reconstructs only facts supported by `audit_log`, labels all
of them `actor = 'backfill'`, and uses the same source identity as live
delivery. It also records legacy `workedAt` values from `timeStart`, then
`createdAt`. I did **not** fabricate historical SLA snapshots: old policy edits
were not preserved as immutable targets, so a plausible-looking snapshot would
be a lie. Each recorded 2.7 snapshot is authoritative; older promises remain
explicitly unknown.
`slaCompliance` therefore returns the earliest snapshot boundary and an
`includesUnrecordedSlaHistory` flag instead of making a pre-snapshot zero look
complete. Legacy status/priority normalization now goes through the ticket
repository before reconstruction, so its audit fact and SLA re-target cannot
diverge from the normalized current row.

The source-identity unique indexes and append-only triggers are startup-critical
and catalog-verified because their absence changes correctness. Range/grouping
indexes are optional performance extras: losing one can slow a report but
cannot change its answer.

## Underspecified points and next work

The spec does not choose a tenant reporting timezone, so the repository exposes
unambiguous UTC buckets and leaves presentation-zone rebucketing to Workstream
B. It also names three SLA states even though an active promise can be neither
at risk nor complete; that is why `onTrack` is explicit.

Prisma validation, the complete Jest suite, and the TypeScript build pass in
this worktree. `npm run test:postgres` now creates a random isolated schema in
an explicitly supplied `POSTGRES_TEST_DATABASE_URL`, executes the real
backfill/percentile/aggregate SQL and append-only triggers, then drops only that
schema. The sandbox could not access the local Docker daemon and no standalone
PostgreSQL server was available, so that opt-in suite could not be executed
here. Workstream B can add the admin REST/MCP report surface and
reconstructed-history labels without changing this data model.
