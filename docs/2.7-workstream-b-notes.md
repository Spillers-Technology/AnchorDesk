# AnchorDesk 2.7 Workstream B — reporting and the TIME calendar

> **Provenance note.** Unlike the sibling workstreams, these notes were not
> written by the implementer. That run was interrupted by a usage limit before
> it committed or documented anything, and the work was recovered from the
> worktree afterwards. What follows is written from the code as merged, so it
> records what the implementation *does*; where it does not explain *why*, that
> is honest ignorance rather than omission.

## What shipped

- `services/reporting.ts` + `repositories/ticketEventRepository.ts` —
  aggregation over the Workstream A fact spine.
- `routes/reports.ts` — `/reports/*` plus the two TIME endpoints
  (`/time/day-spread`, `/time/sla-timeline`).
- `routes/mcpReports.ts` — nine read-only MCP tools: `report_volume`,
  `report_durations`, `report_sla_compliance`, `report_backlog_age`,
  `report_team_throughput`, `report_assignee_throughput`,
  `report_time_by_company`, `get_time_day_spread`, `get_ticket_sla_timeline`.
  All registered in `READ_ONLY_MCP_TOOLS`, so a readonly connection can reach
  them through the single MCP POST transport.
- `components/ReportsView.tsx`, `components/reports/*`,
  `components/timeCalendarModel.ts` — seven report views plus day spread and
  per-ticket SLA timeline.

## Decisions worth recording

**Percentiles are computed in Postgres, not Node.** `percentile_cont(0.5)` and
`(0.9)` with `WITHIN GROUP (ORDER BY minutes)` — continuous interpolation, so
p50 on an even-sized set is the midpoint rather than an arbitrary neighbour.
The rule from the brief held: every duration metric reports p50/p90, and no
mean is presented alone.

**Provenance travels with the data.** `reportProvenance` marks any window that
overlaps backfilled history, and the UI renders it as a banner reading
*"Reconstructed events are estimates, not recorded history."* This is the
Workstream A discipline carried to the surface — the spine refused to fabricate
historical SLA snapshots, and the reports refuse to present what was
reconstructed as though it were recorded.

**Chart colour is a fixed validated palette, not the MUI theme.** Eight
categorical hues with separate light and dark steps, exposed as
`--ad-chart-cat-N` CSS custom properties. Deriving from `theme.palette` would
have been the obvious move and would have silently destroyed colourblind
safety, because AnchorDesk has seven user-selectable palettes. Chart *chrome*
(surface, text, grid) still follows the theme so charts sit correctly in each.

**Every chart has a table view.** Present as a Chart/Table toggle, which also
discharges the contrast-relief obligation for the lighter palette slots.

**The day target is stated as an assumption, not asserted as fact.**
`DEFAULT_DAY_TARGET_MINUTES = 8 * 60`, with the source labelled `default_8h`
and the UI saying *"a reporting default, not a recorded employment schedule."*
There is no staff-schedule model, so the code refuses to imply it knows anyone's
shift.

**Unplaceable time is reported, not dropped.** A duration-only entry has no
start/stop to position on a timeline, so the day spread separates *placed* from
*unplaced* coverage rather than silently omitting entries it cannot draw.
`UnreportableDaySpreadError` covers the case of an entry with no truthful
duration at all.

**Range semantics are explicit.** `[from, to)`, stated in the UI as
"(exclusive)", with UTC calendar day buckets — matching the spine's
normalisation so results do not shift with the database session timezone.

## Defects found on review

Two, both fixed:

1. **The day-spread authorization test asserted against the wrong range.**
   `/time/day-spread` caps its window at 26 hours (a day, plus slack for a DST
   transition), but the test reused the suite's month-long range constant, so
   it failed on the range guard before reaching the RBAC rule it existed to
   check. The implementation was right; the test was wrong. Given its own
   single-day range, plus a new case pinning the cap.

2. **The portal's KB mock shadowed the ranked staff search.** Not a reporting
   defect, but caught by the matrix during this integration: two workstreams
   each registered a `/kb/search` mock handler and the portal's matched
   unconditionally. Scoped to `visibility=portal`.

## Known gaps

- **Business hours are hard-coded.** The 09:00–17:00 / eight-hour default is
  honest about being a default, but it is still an opinion baked into every
  "unlogged time" figure, and the wrong value makes those numbers quietly
  wrong for any shop that does not work those hours. This is a strong toggle
  candidate under the rule in
  [roadmap-configurability.md](roadmap-configurability.md) — reasonable shops
  genuinely differ, and both settings are honest. Tenant-level, probably
  alongside a per-user timezone.
- **Per-user timezone still absent.** Reports bucket by UTC calendar day,
  correctly, but a technician outside UTC sees a "today" that ends at the wrong
  hour. Recorded as the highest-value item in the configurability pass.
- **No CSV export yet** for the time-by-company roll-up, which the 3.0 roadmap
  wants as the billing-export seed.
- **Portfolio-wide SLA timeline** was tier 4 in the brief and did not ship, as
  planned.
